## What this repository is

**Blustery Bulwark of SPLORR!!**, a new game by TheGrumpyGameDev, started November 9, 2026: a more modern take on the *kind* of game Castle of the Winds (Rick Saada, 1989/1993) was, a tile-based fantasy roguelike with towns, shops and a dungeon below a fortress. The name came from "Windy Castle of SPLORR!!" with both words swapped for synonyms.

It is **inspired by, not a remake of** Castle of the Winds. Do not reuse its story, place names, bosses, characters, icons, text or level layouts (no Hrungnir, Surtur, Bjarnhaven, Crossroads, Olaf's Junk Store, Amulet of Kings). Genre mechanics (weight and bulk, identification, curses, shops, towns between dungeons) are fair game.

`DESIGN.md` is the specification. It records the user's decisions (dated, in their words) and open questions; only the user moves an item from Open to Decided. `PLAN.md` is the build plan: slice 1 in ten steps, each ending playable in the browser and tested natively. The user said to build on November 9, 2026; steps 0 (the scaffold), 1 (a floor to walk), 2 (wind and light), 3 (inventory) and 4 (tenants and combat) are done. Work one step at a time and record what changed in `PLAN.md`.

The vault at `/home/yermom/git/bok-of-splorr/splorr/` is the shared body of knowledge for all SPLORR!! games and holds the standing rules. Read its `Home.md` first. This game's note is `Games/Blustery Bulwark of SPLORR!!.md`. When a decision or a fact about the game changes, update that note and its `Home.md` row as well. `Gotchas.md` in the vault has the WebGL, wasm RNG and Odin lessons; read it before writing code.

## Commands

```bash
tools/test.sh                  # native tests (odin test, one thread), wasm checks of both packages, then a real wasm build
tools/build.sh [--size]        # wasm build into build/web (--size for shipping)
tools/serve.sh                 # build and serve on http://localhost:${PORT:-8000}/
tools/pages.sh                 # tests, size build, copy into docs/ for GitHub Pages; never commits or pushes
./shippit.sh [--push]          # tests, size build, zip; butler push to itch.io only with --push (only on the user's "ship")
python3 -I tools/extract_gfx.py [--sheet out.png]  # regenerate src/game/gfx.odin and font.odin (add tiles to PICKS)
python3 -I tools/make_cover.py # regenerate the placeholder assets/cover.png
tools/make_shots.sh            # render a real frame natively: assets/screenshots/01-play.png and assets/portal.png (the portal card picture)
```

The browser pane's launch config `bulwark-web` (port 8766, in the vault's `.claude/launch.json` and this repo's) serves `build/web`; run `tools/build.sh` first. The pane does not run frames until a screenshot is taken.

## Architecture

Odin compiled to `js_wasm32`, a 384 by 216 software framebuffer of Sweetie-16 palette indices drawn to a canvas (no WebGL), as in the vault's `Tech/Odin wasm recipe.md`.

- `src/game/` is the pure rules package (`package game`, no `core:os`, no `core:fmt`; `itoa` makes numbers into text): `game.odin` (state, `Command`, `command`, `pointer`, `tick`, stairs), `floor.odin` (generation, field of view, routes), `wind.odin` (turn processing in `end_turn`, gusts, the torch; the tuning tables `GUST_PERIOD`, `SNUFF_CHANCE`, `TORCH_TURNS` are at its top), `items.odin` (the item pool, the `KIND` table of weights, bulks and capacities, carrying rules, the starting kit, floor items), `inv.odin` (the inventory screen), `hero.odin` (attributes, the creation screen, health, death and waking; `ATTR_*` tuning at its top), `tenants.odin` (the `TENANT` table, spawning, chase-and-wander, hidden-roll combat, gear wear, trophies; `PLAYER_HIT`, `WEAPON_WEAR`, `ARMOUR_WEAR` at its top), `rng.odin` (splitmix64; every floor comes from `floor_seed(character seed, floor number)`, so it is the same on wasm and native), `render.odin` (map view, automap, log, side panel), `screen.odin` (layout constants, `Frame`, palette, `Gfx` enum, drawing and text). `gfx.odin` and `font.odin` are generated by `tools/extract_gfx.py`; never hand-edit them. Tests are `*_test.odin` with `#+build !js` as their first line; the `new_game` helper skips creation and turns tenants off (`no_tenants`) so a test checks one rule alone, and `new_game_with_tenants` keeps them. `dump_test.odin` writes frames to look at: `-define:DUMP_PLAY=`, `DUMP_FIGHT=` or `DUMP_DEAD=<path.ppm>`.
- `src/web/web.odin` (`package main`, `#+build js`) is the thin browser layer, imported as `tggd:game` (`-collection:tggd=src`). odin.js calls the exported `step` each frame (it runs `game.tick`, which walks mouse routes); the page calls `platform_start` with a fresh seed once, copies the RGBA frame when `platform_frame_ready` returns 1, and forwards input through `platform_command` (a `game.Command`) `platform_pointer` (framebuffer pixel and a `game.Pointer`: mouse, right mouse, touch) and `platform_pointer_up` (ends a drag in the inventory). Every log message goes through `say`, which wraps at spaces to `LOG_WIDTH` (41) characters.
- `web/index.html` maps keys (arrows, numpad, Home/End/PgUp/PgDn for diagonals, Space or 5 to wait, Enter, Escape, M or Tab for the map, I for the inventory, F for feedback), the mouse and touch (pointer events), the gamepad (d-pad or stick, A confirm, B cancel, X wait, Y map, Start inventory) and the touch pads (a 3 by 3 d-pad and OK, Back, Map, Pack, shown on the first touch; on screens under 500 px tall the canvas leaves 108 px each side for them) to those calls. The `Command` order there must match `game.odin`. The footer holds the credits, the AI disclosure, the back links and the "Send feedback" link; the LootLocker game is not set up yet (the user's console setup), so the form cannot send until `domain` and `key` are filled in.
- Layout: map view 21 by 15 tiles of 12 px at the top left, a four-line message log under it, the side panel on the right.

## Standing rules (full text in the vault's `Home.md`)

- **"Push" means `git push`; "ship" means itch.io.** Do neither unless the user says that word. One ship a day through Coxswain (`ship_today` before, `ship_complete` after); scheduling is not permission.
- **GitHub Pages first.** The repo is public (`playdeezgames/blustery-bulwark-of-splorr`). **Pages is live since November 9, 2026** at https://playdeezgames.github.io/blustery-bulwark-of-splorr/, served from `main` `/docs`. To update it: `tools/pages.sh`, commit `docs/`, push (each push needs the user's go-ahead).
- **Release standard** from the start (`Tech/Release standard.md`): `ITCH_DESCRIPTION.md`, `assets/cover.png` (630 by 500), `assets/screenshots/`, `devlog/YYYYMMDD/`, `tools/ship.sh` and a one-line `shippit.sh` that pushes only with `--push`. The page footer carries back links, the AI disclosure and a "Send feedback" link to the shared LootLocker form (`Tech/LootLocker.md`).
- **Public repo: no 1-Bit Kingdom art**, ever. Prefer CC0 sets (Urizen, Bountiful Bits, Bit Bonanza) and keep every licence record and credit.
- If the ROM font 8x8 turns up, ask the user before replacing it (DINOBYTE first, then Public Pixel).
- In player-facing text and itch copy the game is a **"Metaphor"**, never a "Game", and the voice says **"yer"**, never "your" or "you're".
- Do not describe or "fix" deliberate design (brutality, odd rules) as a problem once the user has decided it.
- Anything an AI agent posts on itch.io says it was posted by an AI agent.
